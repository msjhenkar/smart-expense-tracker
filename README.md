# Smart Expense Tracker API

A REST API for managing personal expenses — add, view, filter, total, and delete expenses. Built with Spring Boot 4.1.0 and Java 17, using in-memory storage (no database required).

## Tech Stack

- **Java 17** (source/target compatibility, per `pom.xml`) — developed and tested on JDK 25.0.3 runtime, which remains backward-compatible with Java 17 language/API level
- **Spring Boot 4.1.0** (Spring Web MVC, Bean Validation)
- **Maven 3.9.16** (via the included Maven Wrapper — no local Maven install needed; wrapper pins this exact version)
- **JUnit 5 + Mockito** for testing
- In-memory storage via a thread-safe `ConcurrentHashMap`

> Verified via `.\mvnw.cmd -version` on Windows 11.

```
      model/            # Expense entity
      dto/              # Request DTOs + validation
      exceptions/        # Custom exceptions + global handler
    test/java/com/expense_tracker/
      controller/       # Controller-layer tests (MockMvc)
      service/          # Service-layer unit tests
```

> **Note on folder structure:** This project follows standard Maven convention (`src/main/java`, `src/test/java`) rather than a separate top-level `tests/` folder. Maven's build tooling (`mvn test`, dependency resolution, IDE integration) depends on this structure, so a non-standard top-level `tests/` directory would break the build. Source code lives under `src/main`; the full test suite lives under `src/test/java` and runs via the command below.

## Prerequisites

- **Java 17 or higher** installed (`java -version` to check) — developed and tested on JDK 25
- No need to install Maven separately — this project includes the Maven Wrapper (`mvnw` / `mvnw.cmd`), pinned to Maven 3.9.16

## Installation

Clone the repository and navigate into the project root (the folder containing `pom.xml`):

```bash
git clone https://github.com/yourusername/expense-tracker.git
cd expense-tracker
```

**All commands below should be run from this project root.**

Verify you have Java 17 or higher:

```bash
java -version
```

Expected output should show `17` or higher (this project was developed and tested on JDK 25, which remains compatible).

Then download all dependencies and compile:

```bash
# macOS/Linux
./mvnw clean install -DskipTests

# Windows (PowerShell or cmd)
.\mvnw.cmd clean install -DskipTests
```

This compiles the project and downloads all required dependencies without running the test suite.

## Running the Server

```bash
# macOS/Linux
./mvnw spring-boot:run

# Windows (PowerShell or cmd)
.\mvnw.cmd spring-boot:run
```

Look for `Started ExpenseTrackerApplication` near the end of the console output — this confirms the server is up. It will be available at:

```
http://localhost:8080
```

### Running from an IDE (IntelliJ IDEA)

1. Open the project folder in IntelliJ IDEA.
2. Wait for Maven to finish downloading dependencies automatically (progress shown in the bottom status bar).
3. Locate `src/main/java/com/expense_tracker/ExpenseTrackerApplication.java` and click the green run arrow next to the `main` method, or right-click the file and select **Run**.

## API Endpoints

Base URL: `http://localhost:8080/api/expenses`

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/expenses` | Add a new expense |
| `GET` | `/api/expenses` | Get all expenses |
| `GET` | `/api/expenses?category={category}` | Get expenses filtered by category |
| `GET` | `/api/expenses/total` | Get the overall total of all expenses |
| `GET` | `/api/expenses/total?category={category}` | Get the total for a specific category |
| `DELETE` | `/api/expenses/{id}` | Delete an expense by ID |

### Expense object

```json
{
  "id": 1,
  "title": "Groceries",
  "amount": 450.00,
  "category": "Food",
  "date": "2026-07-30"
}
```

- `id` — generated by the server; do not send this on `POST`
- `title` — required, non-blank
- `amount` — required, must be a positive number
- `category` — required, non-blank
- `date` — required, format `YYYY-MM-DD`

### Example requests

**Add an expense**
```bash
curl -X POST http://localhost:8080/api/expenses \
  -H "Content-Type: application/json" \
  -d '{"title":"Groceries","amount":450.00,"category":"Food","date":"2026-07-30"}'
```

**Get all expenses**
```bash
curl http://localhost:8080/api/expenses
```

**Filter by category**
```bash
curl "http://localhost:8080/api/expenses?category=Food"
```

**Overall total**
```bash
curl http://localhost:8080/api/expenses/total
```

**Total for a category**
```bash
curl "http://localhost:8080/api/expenses/total?category=Food"
```

**Delete an expense**
```bash
curl -X DELETE http://localhost:8080/api/expenses/1
```

## Error Handling

- Invalid/missing fields on `POST` return `400 Bad Request` with a field-level error breakdown.
- Deleting a non-existent `id` returns `404 Not Found`.

Example validation error response:
```json
{
  "timestamp": "2026-08-01T09:00:00",
  "status": 400,
  "errors": {
    "amount": "Amount must be positive"
  }
}
```

## Design Decisions

- **In-memory storage**: chosen over a JSON file for simplicity and reliability within the assignment's time scope. Data does not persist across server restarts — this is expected behavior, not a bug. The repository is built behind an `ExpenseRepository` interface, so swapping in file-based or database persistence later would not require changes to the service or controller layers.
- **`BigDecimal` for amounts**: avoids floating-point rounding errors inherent to `double`/`float` for monetary values.
- **Validation at the controller boundary**: request validation (`@Valid` + Bean Validation annotations) happens on the DTO before it reaches the service layer, keeping business logic free of defensive null/range checks.
- **Category matching is case-insensitive** (e.g. `food` and `Food` return the same results).

## Known Limitations

- Data is not persisted; restarting the server clears all expenses.
- No authentication/authorization — out of scope for this assignment.
